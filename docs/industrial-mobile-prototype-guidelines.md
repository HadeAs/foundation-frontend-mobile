# 南瑞物流 App 页面原型设计规则

> 状态：已确认设计基线；料箱绑车/料箱解绑原型已确认；18个菜单的2026-10-12.1正式页面前端适配已全部验收\
> 版本：1.3.71\
> 最后更新：2026-10-21\
> 适用范围：后续新增业务页面、现有页面改版及全局视觉统一。

## 1. 设计目标

原型面向工业 PDA 的高频扫码作业。设计优先级依次为：操作明确、扫码连续、错误可恢复、单手可用、信息紧凑。避免装饰性大留白、复杂动画和依赖悬停的交互。

## 2. 视觉基线

- 原型所有列表复选框（板件解绑、卸车、手动叫料、料箱解绑）统一保持18px尺寸，勾选框与旁边内容水平间距为12px。正式页面保留原有控件尺寸，使用固定12px而非12rpx，移除默认外边距，缩放控件以右侧为原点，避免额外视觉空隙；H5清除组件内部默认右边距。登录“记住账号”的符号与文字拆分后采用同样间距，点击行为不变。
- 主色：`#0D9496`，用于导航栏、主按钮、选中状态和关键交互文字。
- 页面背景使用低饱和浅灰绿；卡片使用白色；边框使用浅青灰。
- 错误使用红色文字与浅红背景；成功使用深青色文字与浅青背景。颜色不能作为唯一状态表达，必须同时有文字。
- 字体采用清晰的系统无衬线字体；正文保持正常字重，标题和关键值使用中等字重。
- 统一使用小圆角、细边框和轻阴影，体现工业工具感，不使用高饱和渐变或大面积装饰。

## 3. 页面骨架

### 3.1 状态栏与导航栏

- 顶部状态栏展示时间、应用名称和设备状态示意。
- 二级页面导航栏左侧为“返回”，标题居中，不放无业务价值的右侧按钮。
- 首页不显示返回按钮。

### 3.2 内容区

- 页面采用紧凑垂直布局，统一左右边距和 6–10px 的组件间距。
- 扫码输入、当前对象信息等关键上下文固定在顶部；超出可视高度的明细列表单独滚动。
- 禁止整个页面横向滚动；320px 宽度下文字、按钮和卡片不得重叠或被裁切。

### 3.3 底部操作区

- 业务确认按钮固定在内容区底部，避免随长列表滚出视野。
- 两按钮：左侧“清空页面”，右侧主操作。
- 三按钮：按业务顺序同排展示，并保证主操作最靠右。
- 主操作使用主色实底；清空使用白底描边；解绑、卸载、取消、锁定等风险操作使用红色描边或红色文字。
- 操作不可用时必须呈禁用态，不能仅在点击后报错。
- 禁用按钮边框统一为灰色 `#B8B8B8`（含 uni-app 默认伪元素边框），保留尺寸、间距及文字灰化反馈；恢复可用后恢复主操作、危险操作或普通按钮的原样式。复合扫码控件的禁用扫码按钮分隔边框也使用该灰色，输入框轮廓不变。

## 4. 扫码输入组件

- 所有作业页复用“扫描录入”模式：输入框与“扫码”按钮同一行并固定在顶部。
- 当前步骤提示直接作为 placeholder，不再额外占用顶部提示块。
- 输入框支持手动输入、相机扫码和 PDA 原生扫描结果写入。
- 页面进入时不自动聚焦，不弹出软键盘；PDA 扫描不得依赖输入框焦点。
- 扫描处理期间禁用重复提交，并显示简短处理中状态。
- 单输入框多阶段页面应根据当前状态自动切换 placeholder，例如“扫描箱码”切换为“扫描物料唯一码”。

## 5. 信息卡片与列表

- 对象卡片采用“标题 + 状态标签 + label/value 信息行”。label 使用弱色，value 使用正文色。
- 编码、名称和状态优先展示；非关键说明放在次级文字中。
- 可删除的待提交记录在卡片右上角显示删除图标；不可删除记录不显示无效删除入口。
- 长列表必须限制在剩余可视高度内滚动；顶部扫描框和当前箱/载具信息保持固定。
- 列表空状态应说明下一步动作；接口无业务数据时使用具体文案，而不是仅显示“暂无数据”。
- 可点击卡片必须整块可点击，并通过文字或箭头体现可操作性。

- 料箱和物料明细统一沿用“物料接收”的列表结构：卡片标题与数量分列；正文保留统一内边距，分隔线随正文缩进；标题固定，仅正文滚动。成品发货、缴库申请、缴库发起同样遵循此规则。

## 6. 状态标签与计数

- 已绑定、待绑定、已识别、空闲、占用等使用紧凑文字标签。
- 列表标题区可显示总数或已选数量，例如“已选 2 / 8”。
- 标签文案必须与真实业务状态一致，不用颜色替代文字。
- 板件扫码绑箱物料卡不显示无意义的“1 件”，改用“已绑定 / 待绑定”。

## 7. 库位三级选择

- 所有库位选择统一为“楼层 → 区域 → 库位名称”三级级联。
- 选中后的统一展示格式：`楼层 / 区域 / 库位名称`；接口提交对应库位编码。
- 物流任务查询返回唯一推荐目标时自动选中并显示完整路径，打开级联时回显该目标；没有推荐或有多个推荐时三个层级初始为空。不因仅有一个未推荐候选而自动选择；自动选中不自动创建任务。
- 切换楼层后清空区域和库位，并禁用库位选择。
- 选择或切换区域后清空库位；三级完整后才启用“确认选择”。
- 呼叫空载具的库位选择框不得包含载具信息；载具编号在选择框外独立展示。
- 呼叫空载具默认选择接口数组首项；页面按“目标位置（编号、名称）→ 起始位置（可选数、级联选择框）→ 框外载具编号及实际内容”展示，底部同排“清空页面 / 确认呼叫”。实际内容显示已确认空载/非空/未确认，不将候选身份当空载确认。无候选显示“暂无可用空载具”并禁用呼叫；成功仅提示“呼叫成功”后恢复初始状态。
- 复用三级位置选择器时按业务设置标题：物流任务为“选择目标位置”，空载具呼叫为“选择起始位置”。位置字段仅含楼层/区域/库位，不混入载具信息。
- 弹窗使用原生选择控件，标签依次为“楼层 / 区域 / 库位名称”。
- 正式页面使用 uni-app `picker` 三级独立选择，每级保留“请选择”占位，不将原生选择器的首项视为已选择；已有选择时回显，无选择时全空，切换楼层清空区域/库位，切换区域清空库位。确认前使用临时选择，取消保留页面原选择（含自动推荐）；级联层级按编码分组，同名不同编码不合并。弹窗最多80vh，中部可滚动、按钮固定。

## 8. 弹窗与反馈

### 8.1 二次确认弹窗

- 仅用于会改变数据关系或状态的操作，例如一键解绑、任务取消、交管锁定/释放。
- 标题明确动作，正文说明对象和影响；按钮使用“取消 / 确认动作”。
- 信息查看弹窗可使用单一“关闭”按钮。
- 呼叫空载具识别目标后再扫码，按原型使用“替换目标位置”确认框，明确将清除原候选，按钮“取消 / 确认替换”；取消保留当前选择及未确认原请求。确认框自然高度、最多80dvh，长正文独立滚动、标题和按钮固定；打开后清除上一条提示并禁用背景扫码/清空。确认呼叫本身直接提交，不增加二次确认。
- 箱内物料弹窗不设置固定正文高度：内容少时自然收缩，正文最大高度为视口的48%，超过后仅正文滚动；弹窗整体不超过视口的80%，标题和底部关闭按钮不随正文滚动。

### 8.2 非阻塞提示

- 成功、失败及校验提示显示在导航栏下方的浮层中，不使用固定红色提示区。
- 浮层使用接近透明的浅色背景、细边框和轻阴影；文字颜色比背景明显更深。
- 正式菜单的短提示和较长错误统一使用 `OperationNotice.vue`；较长文本完整换行，浮层最大高度为视口的 30%，超出后仅浮层内部滚动。新增容器菜单沿用同一规范，不在正式页面复制浮层样式。
- 成功文字为深青色，失败文字为深红色；沿用约 2.5 秒/6.5 秒展示时长，不截断后端原因。
- 普通绑定、解绑、装卸车、位置操作、接收及WMS清理的成功反馈不依赖`operationNo`，不因新版取消该字段显示“回执不完整”，也不补造编号展示。其余必需回执核验通过后沿用原有提示、清空或保留当前箱交互；混料确认仍打开确认框而非提示成功，未知/无效回执仍保留上下文。业务单据/任务编号展示不变；本次不改页面布局或HTML原型。
- 不使用声音或震动反馈。
- WGT轮询及检查失败保持静默，只记诊断；前台恢复检查不新增提示区。发现新版本仍使用原更新确认框、下载进度与安装后重启确认；用户停留期间不得因检查超时或下一轮轮询重复弹框、下载或安装，不自动替用户确认。
- 登录页无导航栏，失败提示复用 `OperationNotice`，固定在页面顶部状态栏安全区下方；红字、浅红半透明背景、细边框及阴影，约 6.5 秒消失。长错误自然换行，超过视口 30% 时内部滚动，不使用居中黑色 Toast，不挤动登录表单。

## 9. 典型页面模板

### 9.1 单对象连续扫码页

适用于板件扫码绑箱、装车：固定扫码框 → 固定当前对象/配对上下文 → 可滚动列表 → 底部操作栏。

板件扫码绑箱实现：扫码框高 76rpx，使用系统字体、浅青灰边框、白色内容卡与 `#0D9496` 主色；底部固定同排“清空页面 / 获取拼板 / 确认装箱”。非空箱确认前不显示已有物料，选择保留后才呈现；确认框请求失败时保持打开，原因仍通过导航栏下浮层展示。失败浮层显示约 6.5 秒，成功提示约 2.5 秒。首页设计范围为18个菜单；正式应用已完成18个的新版前端适配及用户前端验收，不跳转无关旧页面。

装车沿用单一扫码页：顶部固定扫码框与“已完成N对”统计，待补充箱子时 placeholder 提示当前对序号；中部配对卡独立滚动，卡内按“载具库位号 / 载具编号 / 箱子编号”展示，未扫箱时显示“—”。卡右上角删除图标，标签区分“待扫描箱子 / 待装载”。底部同排“清空页面 / 确认装载（N）”；未完成配对或请求中禁用提交，禁用边框沿用全局灰色。初始空状态无额外滚动，提示与错误沿用导航下方浮层。

装车新版：每张配对卡在箱码下固定增加“实际内容”行，未识别箱子为“—”，识别后显示未确认/已确认空载/已确认非空；内容字段缺省显示未确认，不因允许装车显示空箱。待补充与已完成卡沿用同一字段骨架，编码允许换行，标签和删除入口不被挤压。直接绑定或其他资格失败显示后端原因，保留待扫描箱子阶段，不增加自动解绑弹窗。失败或异常回执保留配对供手动重试，只有完成回执通过才恢复初始状态。空列表关闭滚动，长列表仅正文滚动；隐藏后清空页面，不改HTML原型或其他菜单。

“获取拼板”仅在本次待绑定板件至少一条且无处理中/确认弹窗时可用。仅有已绑定板件时禁用；删除最后一条待绑定板件或清空页面后立即恢复禁用，边框沿用全局灰色。空候选提示“没有新的可加入板件”，保留现有列表；失败、超出提交上限不得部分加入。

板件扫码绑箱新版：箱卡在编号下紧凑显示“实际内容”，区分未确认、已确认空载、已确认非空，不根据列表长度显示空箱。已绑定物料行增加“批次”及原文本值；候选批次有值才显示。名称、单位缺省时直接省略，不留下孤立分隔符或补默认文字。数量绑箱已有行保留查看，但不能与本次唯一码方式混用。

混料待确认复用白底二次确认框：标题“混料确认”，正文完整显示后端原因，按钮“取消 / 继续装箱”。长正文滚动，弹窗最多80dvh，底部操作始终可见。提示期间保持箱卡、数量与列表不变，不显示成功；背景扫码、删除、清空、获取拼板和提交均禁用。取消保留页面；继续请求失败保留提示与数据，凭据/版本冲突关闭过期提示并用导航下失败浮层要求重扫。仅最终绑定回执成功后恢复初始状态；不新增用途选择、尾单入口或固定提示区。HTML原型本轮不修改，其余菜单等待逐项改造。

板件快捷绑箱沿用相同紧凑单一扫码骨架：先扫箱码，再将placeholder切换为“扫描或输入代表板件唯一码”。顶部固定箱编号、实际内容和已绑定数量；同数量方式已有绑定直接进入追加页，跨方式才显示一键解绑确认，选择否恢复初始状态。正文卡内订单只读回显、右侧数字数量可输入，下方显示实际代表码、物料信息和可用批次；长代表码换行，名称/批次缺省省略。底部固定同排“清空页面 / 确认装箱”。混料弹窗复用上述规范，期间数量输入和背景扫码、清空、提交均禁用，保持原内容；冲突后保留数据但禁用旧快照提交，要求清空重扫。初始空内容不滚动，320px下订单与数量不横向溢出；不添加手填订单或用途选择。

### 9.2 查询列表页

适用于待接收物料清单、取消物流任务、交通管制：固定查询条件 → 可滚动结果列表。查询条件只保留已确认的业务字段，不增加推测性筛选。

待接收物料清单：顶部载具号、库位号输入与“查询”同排，76rpx高；下方白色列表卡标题与“已加载 / 总数”固定，仅正文滚动。记录按任务号、载具号（箱任务显示箱号）、库位号、接收状态与整批已接收/总箱数、创建时间五行左对齐展示；进度用正文色和明确文字，不以颜色代替状态，不展示内部任务ID/版本，不添加逐箱完成标记。可信库位缺省显示“—”，不补造位置或空载。

支持下拉刷新，底部显示加载中、暂无待接收物料清单、上滑加载更多、已加载全部任务或“加载失败，点击重试”；具体失败原因沿用导航栏下方红色浮层。无底部业务按钮、接收动作、详情跳转或资格筛选。分页/记录异常与网络失败同样保留已有清单和重试入口，不能渲染破损记录。隐藏后不接受旧触底/刷新事件，重新显示查询第一页。保持紧凑主色布局，空状态无额外页面滚动，320px下输入、长编码、状态及时间可换行且不横向溢出；HTML原型本轮不调整。

取消物流任务：固定顶部ScanInput，placeholder为“容器码/AGV编号或名称”，不增加品牌/类型筛选。任务卡保留编号/品牌、单行AGV（未分配为“—”）、容器、起始/目标位置、当前状态、发起方式及时间；小型取消按钮仍位于状态/发起方式右侧水平对齐，不按运输状态隐藏。缺省容器当前位置不补造起点或终点，不增加未确认的实际内容明细。

取消二次确认少量内容自然收缩，白底弹窗最多80dvh，只有长正文滚动、标题及两按钮固定；背景扫码、刷新、触底和未决结果核查禁用，ACCEPTED轮询暂停，取消确认后恢复。查询/回执失败沿用导航下较长红色浮层；处理中/未知的原请求卡独立于任务列表显示“刷新取消结果”，只查询、不重发。ACCEPTED统一说明“取消请求处理中，最终结果待确认，不代表调度已受理”，恢复旧记录也使用新文案；404在保留后端原因后追加“不代表未发送或已过期”，不得显示可以重新取消。存储异常使用同类白色只读卡说明需核实，按钮保留但禁用，不新增固定红色错误区、声音或震动。隐藏关闭确认并停止轮询；迟到回执只同步原请求及对应任务，不弹过期提示或刷新新视图。保持375px/320px的初始无额外滚动及长列表内部滚动，HTML原型本轮不修改。

### 9.3 两对象确认页

## 11. 交互状态完整性

每个新页面原型必须覆盖以下状态：

1. 初始状态：清楚说明首次扫描或输入内容。
2. 加载状态：防止重复扫码和重复提交。
3. 有数据状态：展示关键对象、列表和可执行动作。
4. 空数据状态：说明当前对象为何不能继续或下一步怎么做。
5. 校验失败：保留可修正数据并显示明确原因。
6. 请求失败：页面保持，允许重试。
7. 提交成功：提示成功并按业务规则清空页面。
8. 长列表状态：固定顶部上下文与底部操作，列表独立滚动。

## 12. PDA 与可用性要求

- 原型默认按 320–440px 移动端宽度设计，并重点检查 320px。
- 主要按钮应有足够触控面积；紧凑行内按钮仍需保持清晰边界和可点击性。
- 控件使用原生按钮、输入框和选择框，保留键盘焦点样式。
- 不依赖 hover；重要操作、状态和错误必须始终可见。
- 编码和长文本允许换行，但不得挤压状态标签或操作按钮。
- 真实 PDA 验收应覆盖不聚焦扫码、连续扫码、物理扫描键和 Android 返回键。
- 业务页的 H5 键盘扫码统一使用 `useKeyboardScanner`，输入框聚焦时不重复提交；禁用、清空及离页时清除缓存，页面隐藏或卸载时停止监听。原生 PDA 广播仍使用 `usePdaScanner`。

## 13. 原型交付与变更规则

- 原型是业务 SPEC 的可视化补充，不能代替业务规则和接口契约。
- 新功能按“业务规则确认 → 页面流程 → 状态设计 → 可点击原型 → PDA 窄屏验证 → 用户确认”的顺序推进。
- 每次功能变更必须同步更新：业务 SPEC、本文规则（如涉及共性）、可点击原型和回归检查。
- 共性样式应修改共享规则，不在单页复制例外；确需例外时在本文件“特殊页面规则”中说明。
- 已确认原型作为版本基线；未经确认的新方案不得覆盖已确认交互。
