# 南瑞物流 App 页面原型设计规则

> 状态：已确认设计基线  
> 版本：1.3.31\
> 最后更新：2026-09-18\
> 适用范围：后续新增业务页面、现有页面改版及全局视觉统一。

## 1. 设计目标

原型面向工业 PDA 的高频扫码作业。设计优先级依次为：操作明确、扫码连续、错误可恢复、单手可用、信息紧凑。避免装饰性大留白、复杂动画和依赖悬停的交互。

## 2. 视觉基线

- 主色：`#0D9496`，用于导航栏、主按钮、选中状态和关键交互文字。
- 页面背景使用低饱和浅灰绿；卡片使用白色；边框使用浅青灰。
- 错误使用红色文字与浅红背景；成功使用深青色文字与浅青背景。颜色不能作为唯一状态表达，必须同时有文字。
- 字体采用清晰的系统无衬线字体；正文保持正常字重，标题和关键值使用中等字重。
- 统一使用小圆角、细边框和轻阴影，体现工业工具感，不使用高饱和渐变或大面积装饰。

## 3. 页面骨架

### 3.1 状态栏与导航栏

- 顶部状态栏展示时间、应用名称和设备状态示意。
- 二级页面导航栏左侧为“返回”，标题居中，不放无业务价值的右侧按钮。
- 首页不显示返回按钮。

### 3.2 内容区

- 页面采用紧凑垂直布局，统一左右边距和 6–10px 的组件间距。
- 扫码输入、当前对象信息等关键上下文固定在顶部；超出可视高度的明细列表单独滚动。
- 禁止整个页面横向滚动；320px 宽度下文字、按钮和卡片不得重叠或被裁切。

### 3.3 底部操作区

- 业务确认按钮固定在内容区底部，避免随长列表滚出视野。
- 两按钮：左侧“清空页面”，右侧主操作。
- 三按钮：按业务顺序同排展示，并保证主操作最靠右。
- 主操作使用主色实底；清空使用白底描边；解绑、卸载、取消、锁定等风险操作使用红色描边或红色文字。
- 操作不可用时必须呈禁用态，不能仅在点击后报错。
- 禁用按钮边框统一为灰色 `#B8B8B8`（含 uni-app 默认伪元素边框），保留尺寸、间距及文字灰化反馈；恢复可用后恢复主操作、危险操作或普通按钮的原样式。复合扫码控件的禁用扫码按钮分隔边框也使用该灰色，输入框轮廓不变。

## 4. 扫码输入组件

- 所有作业页复用“扫描录入”模式：输入框与“扫码”按钮同一行并固定在顶部。
- 当前步骤提示直接作为 placeholder，不再额外占用顶部提示块。
- 输入框支持手动输入、相机扫码和 PDA 原生扫描结果写入。
- 页面进入时不自动聚焦，不弹出软键盘；PDA 扫描不得依赖输入框焦点。
- 扫描处理期间禁用重复提交，并显示简短处理中状态。
- 单输入框多阶段页面应根据当前状态自动切换 placeholder，例如“扫描箱码”切换为“扫描物料唯一码”。

## 5. 信息卡片与列表

- 对象卡片采用“标题 + 状态标签 + label/value 信息行”。label 使用弱色，value 使用正文色。
- 编码、名称和状态优先展示；非关键说明放在次级文字中。
- 可删除的待提交记录在卡片右上角显示删除图标；不可删除记录不显示无效删除入口。
- 长列表必须限制在剩余可视高度内滚动；顶部扫描框和当前箱/载具信息保持固定。
- 列表空状态应说明下一步动作；接口无业务数据时使用具体文案，而不是仅显示“暂无数据”。
- 可点击卡片必须整块可点击，并通过文字或箭头体现可操作性。

- 料箱和物料明细统一沿用“物料接收”的列表结构：卡片标题与数量分列；正文保留统一内边距，分隔线随正文缩进；标题固定，仅正文滚动。成品发货、缴库申请、缴库发起同样遵循此规则。

## 6. 状态标签与计数

- 已绑定、待绑定、已识别、空闲、占用等使用紧凑文字标签。
- 列表标题区可显示总数或已选数量，例如“已选 2 / 8”。
- 标签文案必须与真实业务状态一致，不用颜色替代文字。
- 板件扫码绑箱物料卡不显示无意义的“1 件”，改用“已绑定 / 待绑定”。

## 7. 库位三级选择

- 所有库位选择统一为“楼层 → 区域 → 库位名称”三级级联。
- 选中后的统一展示格式：`楼层 / 区域 / 库位名称`；接口提交对应库位编码。
- 物流任务查询返回唯一推荐目标时自动选中并显示完整路径，打开级联时回显该目标；没有推荐或有多个推荐时三个层级初始为空。不因仅有一个未推荐候选而自动选择；自动选中不自动创建任务。
- 切换楼层后清空区域和库位，并禁用库位选择。
- 选择或切换区域后清空库位；三级完整后才启用“确认选择”。
- 呼叫空载具的库位选择框不得包含载具信息；载具编号在选择框外独立展示。
- 呼叫空载具默认选择接口数组首项；页面按“目标位置（编号、名称）→ 起始位置（可选数、级联选择框）→ 框外空载具编号”展示，底部同排“清空页面 / 确认呼叫”。无候选显示“暂无可用空载具”并禁用呼叫；成功仅提示“呼叫成功”后恢复初始状态。
- 复用三级位置选择器时按业务设置标题：物流任务为“选择目标位置”，空载具呼叫为“选择起始位置”。位置字段仅含楼层/区域/库位，不混入载具信息。
- 弹窗使用原生选择控件，标签依次为“楼层 / 区域 / 库位名称”。
- 正式页面使用 uni-app `picker` 三级独立选择，每级保留“请选择”占位，不将原生选择器的首项视为已选择；已有选择时回显，无选择时全空，切换楼层清空区域/库位，切换区域清空库位。确认前使用临时选择，取消保留页面原选择（含自动推荐）；级联层级按编码分组，同名不同编码不合并。弹窗最多80vh，中部可滚动、按钮固定。

## 8. 弹窗与反馈

### 8.1 二次确认弹窗

- 仅用于会改变数据关系或状态的操作，例如一键解绑、任务取消、交管锁定/释放。
- 标题明确动作，正文说明对象和影响；按钮使用“取消 / 确认动作”。
- 信息查看弹窗可使用单一“关闭”按钮。
- 呼叫空载具识别目标后再扫码，按原型使用“替换目标位置”确认框，明确将清除原候选，按钮“取消 / 确认替换”；取消保留当前选择。确认呼叫本身直接提交，不增加二次确认。
- 箱内物料弹窗不设置固定正文高度：内容少时自然收缩，正文最大高度为视口的48%，超过后仅正文滚动；弹窗整体不超过视口的80%，标题和底部关闭按钮不随正文滚动。

### 8.2 非阻塞提示

- 成功、失败及校验提示显示在导航栏下方的浮层中，不使用固定红色提示区。
- 浮层使用接近透明的浅色背景、细边框和轻阴影；文字颜色比背景明显更深。
- 15 个菜单的短提示和较长错误统一使用 `OperationNotice.vue`；较长文本完整换行，浮层最大高度为视口的 30%，超出后仅浮层内部滚动。不在页面复制浮层样式。
- 成功文字为深青色，失败文字为深红色；沿用约 2.5 秒/6.5 秒展示时长，不截断后端原因。
- 不使用声音或震动反馈。
- 登录页无导航栏，失败提示复用 `OperationNotice`，固定在页面顶部状态栏安全区下方；红字、浅红半透明背景、细边框及阴影，约 6.5 秒消失。长错误自然换行，超过视口 30% 时内部滚动，不使用居中黑色 Toast，不挤动登录表单。

## 9. 典型页面模板

### 9.1 单对象连续扫码页

适用于板件扫码绑箱、装车：固定扫码框 → 固定当前对象/配对上下文 → 可滚动列表 → 底部操作栏。

板件扫码绑箱实现：扫码框高 76rpx，使用系统字体、浅青灰边框、白色内容卡与 `#0D9496` 主色；底部固定同排“清空页面 / 获取拼板 / 确认装箱”。非空箱确认前不显示已有物料，选择保留后才呈现；确认框请求失败时保持打开，原因仍通过导航栏下浮层展示。失败浮层显示约 6.5 秒，成功提示约 2.5 秒。首页完整展示原型 15 个菜单，未开发项点击提示尚未开发，不跳转无关旧页面。

装车沿用单一扫码页：顶部固定扫码框与“已完成N对”统计，待补充箱子时 placeholder 提示当前对序号；中部配对卡独立滚动，卡内按“载具库位号 / 载具编号 / 箱子编号”展示，未扫箱时显示“—”。卡右上角删除图标，标签区分“待扫描箱子 / 待装载”。底部同排“清空页面 / 确认装载（N）”；未完成配对或请求中禁用提交，禁用边框沿用全局灰色。初始空状态无额外滚动，提示与错误沿用导航下方浮层。

“获取拼板”仅在本次待绑定板件至少一条且无处理中/确认弹窗时可用。仅有已绑定板件时禁用；删除最后一条待绑定板件或清空页面后立即恢复禁用，边框沿用全局灰色。空候选提示“没有新的可加入板件”，保留现有列表；失败、超出提交上限不得部分加入。

### 9.2 查询列表页

适用于待接收物料清单、取消物流任务、交通管制：固定查询条件 → 可滚动结果列表。查询条件只保留已确认的业务字段，不增加推测性筛选。

待接收物料清单：顶部载具号、库位号输入与“查询”同排，76rpx高；下方白色列表卡标题与“已加载 / 总数”固定，仅正文滚动。记录按任务号、载具号（箱任务显示箱号）、库位号、创建时间四行左对齐展示。支持下拉刷新，底部显示加载中、暂无待接收物料清单、上滑加载更多、已加载全部任务或“加载失败，点击重试”；具体失败原因沿用导航栏下方红色浮层。无底部业务按钮、接收动作或详情跳转。空状态不得产生额外页面滚动，小屏查询框不横向溢出。

### 9.3 两对象确认页

适用于位置绑定：固定扫码框 → 库位信息 → 容器信息 → 底部操作。已绑定容器时禁用扫码框，显示“清空页面 / 解绑容器”；空闲库位可扫描载具或箱子，显示“清空页面 / 确认绑定”。解绑需二次确认，成功后清空页面，失败保留信息。

位置绑定实现沿用 76rpx 扫码框、紧凑 label/value 信息行及底部双按钮。库位卡展示编号、名称、类型和“空闲/已占用”；容器卡展示编号、类型和“待绑定/已绑定”。待绑定容器识别后同样锁定扫码框，使用清空换对象。初始无额外滚动；小屏或长信息仅中部滚动，导航、扫码框、底部按钮固定。解绑失败保持确认框，原因通过导航下较长红色浮层展示；禁用边框统一灰色。类型字典未知值按后端原值展示，缺省显示“—”。

### 9.4 三级位置选择页

适用于发起物流任务、呼叫空载具：扫描识别对象 → 显示起始/目标上下文 → 点击位置选择 → 三级级联 → 确认业务操作。

### 9.5 扫码勾选解绑页

空状态卡片的顶部间距由滚动容器的内边距承担，不使用首个子项的顶部外边距，避免与 uni-app 的百分比高度内容层发生外边距折叠。空内容须验证滚动高度等于可视高度；长列表须验证可滚动且导航、箱信息、底部按钮位置不变，不通过隐藏滚动条掩盖溢出。

板件解绑固定顶部扫码框、箱信息和已选统计，仅明细区域滚动。明细左侧复选框、右侧实际数量，中间展示板件或物料信息；数量绑定行标明“按订单数量绑定 · 整条解绑”。底部同排“清空页面 / 全部解绑 / 解绑所选（数量）”，不提供全选。两种解绑均确认对象和关系条数；取消保留选择，成功清空，失败保持确认框并在导航下方显示原因。重复扫码不能反选已勾选项。

## 10. 特殊页面规则

卸车沿用扫码勾选模板：顶部固定扫码框、载具信息及“载具内箱 / 已选N / 总箱数”；仅已装箱明细滚动，每行左侧复选框、中间箱码与载具库位、右侧“1箱”。空库位不渲染为可选箱，空载具明确提示无已装载箱子。底部同排“清空页面 / 全部卸载 / 卸载所选（N）”，不提供全选；两种卸载均二次确认。成功清空，失败保留确认框与选择，原因使用导航栏下方较长红色浮层；禁用边框沿用灰色。初始及空载具状态不得产生额外滚动。

- 物料接收底部按钮顺序固定为“清空页面 / 清空 WMS 历史 / 确认接收”。
- “清空 WMS 历史”为独立操作：取得当前接收任务及对象后，可在确认接收前执行，不要求用户先点击“确认接收”，也不与接收动作串联执行；无当前任务时禁用。
- 物料接收实现：顶部固定统一扫码框及接收信息（任务号、对象编号、来源位置、总件数）；来源位置缺省显示“—”，不伪造接口未提供的载具库位号。载具内箱/箱内物料卡标题固定，仅正文滚动。明细使用共享 MaterialRows，箱内弹窗沿用48vh正文/80vh整体上限，少量内容自然收缩。
- 底部三个按钮使用紧凑24rpx文字并同排固定。WMS 清理二次确认说明对象及不自动接收，取消保留页面；清理/接收成功恢复初始状态，失败保留数据和确认框，原因在导航下红色浮层显示。不增加卸车跳转或声音/震动反馈。
- 取消物流任务卡片中，AGV 编号和名称同一行；起始位置与目标位置分两行，不使用“A / B”。
- 取消物流任务顶部固定统一 `ScanInput`，右侧“扫码”，移除独立查询按钮；placeholder 为“容器码/AGV编号或名称”。扫码或手动回车查询，清除恢复全部任务。结果卡显示任务号、品牌标签、AGV、关联容器、起始/目标位置、状态、发起方式及本地时间；不展示任务类型，不增加品牌筛选。小尺寸红边“取消任务”位于当前状态/发起方式两行右侧并垂直居中，发起时间单独一行，不额外占用底部按钮行；点击二次确认。
- 取消已受理与最终成功严格区分；滚动区顶部的结果卡展示任务号、当前原因及“刷新取消结果”，即使任务退出列表也保留。受理中自动查询，未知结果或查询失败保留手动查询入口；失败原因同时用导航栏下方红色浮层提示。结果未确认仅禁用对应任务的取消按钮，不隐藏按钮。
- 交管卡片顶部展示区域和状态；下方左侧两行展示“最后操作人 / 操作时间”，紧凑操作按钮位于右侧并与两行信息水平居中对齐。
- 交通管制顶部固定两行查询区：第一行“区域编号或名称”输入与“查询”，第二行状态选择与“下拉刷新”。只滚动区域卡片列表，空列表无额外页面滚动。时间显示完整本地日期时间，窄屏允许值换行，标签与操作按钮不重叠。
- 交通管制“空闲/锁定”为浅青标签/红边按钮，“占用/释放”为浅橙标签/浅青按钮；小按钮高60rpx。二次确认框随内容自适应，成功更新卡片不清空列表；失败保留确认框、列表并在导航下显示较长红色浮层。无操作历史用“—”，不伪造操作者或时间。
- 首页菜单采用三列宫格，入口全部可见；菜单权限暂不影响原型展示。
- 个人头像使用姓名首字符，英文转大写；个人信息页必须展示当前版本号。

## 11. 交互状态完整性

每个新页面原型必须覆盖以下状态：

1. 初始状态：清楚说明首次扫描或输入内容。
2. 加载状态：防止重复扫码和重复提交。
3. 有数据状态：展示关键对象、列表和可执行动作。
4. 空数据状态：说明当前对象为何不能继续或下一步怎么做。
5. 校验失败：保留可修正数据并显示明确原因。
6. 请求失败：页面保持，允许重试。
7. 提交成功：提示成功并按业务规则清空页面。
8. 长列表状态：固定顶部上下文与底部操作，列表独立滚动。

## 12. PDA 与可用性要求

- 原型默认按 320–440px 移动端宽度设计，并重点检查 320px。
- 主要按钮应有足够触控面积；紧凑行内按钮仍需保持清晰边界和可点击性。
- 控件使用原生按钮、输入框和选择框，保留键盘焦点样式。
- 不依赖 hover；重要操作、状态和错误必须始终可见。
- 编码和长文本允许换行，但不得挤压状态标签或操作按钮。
- 真实 PDA 验收应覆盖不聚焦扫码、连续扫码、物理扫描键和 Android 返回键。
- 业务页的 H5 键盘扫码统一使用 `useKeyboardScanner`，输入框聚焦时不重复提交；禁用、清空及离页时清除缓存，页面隐藏或卸载时停止监听。原生 PDA 广播仍使用 `usePdaScanner`。

## 13. 原型交付与变更规则

- 原型是业务 SPEC 的可视化补充，不能代替业务规则和接口契约。
- 新功能按“业务规则确认 → 页面流程 → 状态设计 → 可点击原型 → PDA 窄屏验证 → 用户确认”的顺序推进。
- 每次功能变更必须同步更新：业务 SPEC、本文规则（如涉及共性）、可点击原型和回归检查。
- 共性样式应修改共享规则，不在单页复制例外；确需例外时在本文件“特殊页面规则”中说明。
- 已确认原型作为版本基线；未经确认的新方案不得覆盖已确认交互。

## 14. 原型验收清单

- 页面标题、返回和底部按钮符合模板。
- 扫码 placeholder 与当前步骤一致，页面不自动聚焦。
- 主色、卡片、标签、危险操作和提示风格统一。
- 320px 下无横向滚动、遮挡或文字截断。
- 长列表可滚动，顶部上下文和底部操作保持可见。
- 清空、删除、确认、失败重试和二次确认均可点击演示。
- 级联选择正确清空下级并阻止不完整提交。
- 成功后清空，失败后保留数据。

位置绑定的“库位已绑载具 / 库位已绑箱子”示例按钮仅在原型演示区展示，不作为正式业务页面按钮。

## 15. 成品发货与缴库页面模板

- 三个新增入口分别追加到库房作业、常规作业、物流作业末尾。
- 单一扫码框固定顶部；对象信息固定；关联料箱或物料明细在剩余空间独立滚动；底部固定“清空页面 / 业务操作”。
- 成品发货支持位置/料车/料箱；缴库申请支持载具/箱子；缴库发起支持载具/位置。placeholder 明确可扫描对象。
- 点击料箱弹窗展示物料；直接扫描箱子展示物料列表；无勾选和部分提交操作。
- 缴库申请实现：对象卡固定展示扫描编码、容器编号、当前位置及关联物料总件数；列表标题与数量固定，仅正文滚动。箱内弹窗标题右侧显示“箱码 · 总件数”，正文同用物料列表样式并可滚动，底部单一“关闭”。无可处理物料显示明确空状态并禁用申请；未知位置显示“—”。小屏无水平溢出、空状态无额外滚动，禁用按钮边框沿用灰色；多单号成功提示允许换行，超长提示限制高度并可滚动。
- 新扫码直接替换当前对象，不二次确认；提交不二次确认，处理中禁用扫码和操作按钮。
- 缴库发起默认选中推荐目标，多个目标可三级切换，单个目标直接显示。无目标地点与条件不满足统一作为扫描失败，仅显示后端返回原因的失败浮层，不展示独立业务状态或重新获取按钮。
- 缴库发起扫描位置若关联料箱，同样作为扫描失败：导航栏下方红色浮层提示“当前位置绑定的是料箱，不允许缴库发起”，不展示本次对象、物料或目标，确认发起禁用；重新扫描关联载具的位置可继续作业，不新增独立状态区。
- 缴库发起复用统一扫码框，placeholder 为“扫描或输入载具/位置编码”；对象信息和目标地点固定，关联料箱卡片标题固定、明细独立滚动。默认推荐显示完整“楼层 / 区域 / 库位名称”，多候选显示“切换”，单候选仅展示路径。
- 点击关联料箱打开自适应高度的“箱内物料”弹窗，右上角展示箱码与总件数，超过上限仅明细滚动，底部关闭固定。底部操作为“清空页面 / 确认发起”；成功显示任务编号后恢复初始空状态，失败保留数据。
- 料车成品发货成功且后端允许后续创建时，询问是否创建物流任务；选择是自动携带料车及发货单号进入任务创建并查询最新信息，选择否结束。目标遵循唯一推荐自动选中规则，仍须手动确认创建，不能跳转即自动创建。跳转处理中锁定询问按钮，失败保留询问框并提示可重试。其余成功结果通过导航栏下浮层展示单号并清空。
- 成品发货正式页面沿用缴库申请样式：固定扫码框和对象卡、仅明细列表滚动、底部同排“清空页面 / 成品发货”。料箱弹窗少量内容按内容收缩，正文上限48vh、整体上限80vh，标题与关闭按钮固定；位置扫描保留原始扫描码并展示解析出的实际容器，错误浮层位于导航栏下方。
- 原型演示区提供载具、料箱、位置、无数据、长列表、提交失败、单个/多个推荐地点、统一扫描失败示例。技术处理顺序不作为正式页面操作步骤。

- 新业务原型演示区的场景选择与演示扫码按钮等宽、等高并排显示，说明文字独占上方一行；窄屏下两列等比分配可用宽度。
