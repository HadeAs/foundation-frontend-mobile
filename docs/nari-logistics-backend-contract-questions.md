## 本轮已明确的前端调整

- 缴库申请、成品发货及接收页 WMS 清理在提交前保存原 UUID 和完整请求，按账号、环境隔离；结果不明时不允许清空或新扫码覆盖，重进页面不自动提交，仅允许人员重试原请求。
- WMS 清理返回后，无论成功或失败，都按原任务 ID 和扫描对象重新查询任务版本；新的查询版本不替换未决清理请求里的旧版本。
- 交管操作成功后重新查询第一页，避免用历史重放回执执行下一次操作；刷新失败时禁止再次操作，先重试查询。
- 请求契约检查限定原有 45 项 PDA 接口，不把合并进来的基座、CRUD、厂商回调当作前端缺失功能。
- 本轮将普通取消和位置解绑关联取消的ACCEPTED统一表述为“处理中，最终结果待确认，不代表调度已受理”，包括旧记录恢复；404仍保留原关联，查询404追加“不代表未发送或已过期”的提示。
- 成品发货对象卡明确提示按箱清理WMS、不按状态或申请号隔离、可能影响同箱其他申请；接收清理保留原有二次确认范围提示。不新增接口参数或额外确认步骤。

以下问题按接口归属整理。建议后端给出稳定的业务错误码或结构化状态及示例，不依赖前端解析中文 `message`；字段命名和是否新增接口由后端确定。

## 1. 缴库申请：明确拒绝与已执行/未知结果无法区分

**接口：** `POST /api/v1/business/nari-logistics/warehouse-applications/submit`

- 已明确：MES拒绝/失败、TOKEN失败、SAP未发送/全部拒绝等无SAP/WMS效果的分支，只有失败及保护释放已经持久化并经核实后，才能刷新、新UUID；原请求仍回放原失败。SAP成功/WMS明确失败必须原UUID、原内容及旧版本仅补WMS；可信WMS成功检查点仅补本地完成。部分成功、未知或SENDING保留保护，不再次发送外部请求。
- 仍缺：这些内部检查点没有结构化公开。409同时包含明确失败、处理中、部分成功与未知；503也不能决定是否可新UUID，统一错误`data=null`。需提供关联原UUID的机器可判别结果、保护释放证据及部分成功/未知人工核查恢复入口，不能解析message中的状态名。
- 示例至少覆盖：MES 明确失败、MES 不可用且未调用 SAP、SAP 全部拒绝、SAP 部分成功/未知、SAP 成功但 WMS 明确失败、WMS 成功但本地结果保存中断、最终成功重放。
- 前端暂行：409/408/5xx/网络异常/无效回执保留原请求；原请求重试仍失败也不擅自解锁。明确无外部效果但仍返回这些状态的申请，当前可能继续处于待核实状态，需契约补齐后放开新申请。

## 2. 接收页 WMS 清理：何时能使用新 UUID

**接口：** `POST /api/v1/business/nari-logistics/receiving/clear-wms-bindings`  
**关联查询：** `GET /api/v1/business/nari-logistics/receiving/tasks`

- 已明确：配置缺失可在登记前失败；登记后的明确失败/回滚与提交未知仍共用HTTP503、`code=500`、`data=null`。SENDING/UNKNOWN重试可返回409并阻止重删；原请求可回放原失败。任务查询只刷新接收范围/版本，不能证明原清理回滚或完成，即使任务已接收、版本增加也不能解锁。
- 仍缺：可机器判别的未发送/明确回滚/处理中/未知/完成状态及其原UUID、任务、范围关联；允许刷新后新UUID的可信条件，以及未知转终态的核实途径。任务查询不能代替这一证明。
- 示例至少覆盖：配置不可用且未删除、事务明确回滚、提交结果未知、SENDING、成功原请求重放、整车跳过已清理箱、零匹配远端行。
- 前端暂行：503 保留原 UUID、任务、对象及旧版本，只支持人工点击原请求重试，由后端阻止重复删除；不实现“503 后自动新 UUID”。每次返回后查询原任务，查询失败不继续使用旧快照接收或清理。
- 已明确无需新增：`affectedCount` 是本次完成清理的箱数，不是远端删除行数；零匹配行仍可完成，不根据数量推算任务新版本。

## 3. 成品发货：未知/中断后的结果核实与解锁

**接口：** `POST /api/v1/business/nari-logistics/shipping/submit`

- 已明确：503可能LES已重建。明确WMS清理失败只能原请求、旧版本补原范围清理，不重做LES；来源变化保护不允许改用新WMS内容。SENDING/UNKNOWN不重删，只有已保存最终回执才是完成；现有对象查询及后台只读检查不能代替原请求终态。
- 仍缺：原UUID结果核实及人工恢复入口、人工处理后取回回执和允许新业务的条件。当前未配置自动过期不等于永久保存保证；须补保留期限、归档/清理及记录缺失、损坏、过期的安全协议，前端不能用经过时长、404或新对象快照解锁。
- 示例至少覆盖：LES 重建完成但 WMS 失败、WMS 来源变化、远端提交未知、本地结果保存中断、成功重放与人工核查完成。
- 前端暂行：持久化原 UUID 和完整请求（包括旧 version），仅手动原样重试，不新建发货、不回滚 LES、不自行选择恢复阶段；未有可信完成回执前不显示成功或询问创建物流任务。

## 4. 取消物流任务：未发送、发送中与不可查询结果的区分

**接口：** `POST /api/v1/business/nari-logistics/logistics/tasks/{taskId}/cancel`  
**结果查询：** `GET /api/v1/business/nari-logistics/logistics/tasks/{taskId}/cancellation`

- 已明确：FLOW在发送前拒绝，当前不登记本次取消记录；支持的外部取消先登记SENDING。ACCEPTED包含内部SENDING，不证明请求已发到厂商或厂商已接受。查询404只说明没有可见可信结果，也可能未登记/未提交/任务不可见，不证明未发送或已过期。旧“只取消未发送本地任务”说明已删除。
- 仍缺：未支持且未发送的稳定业务标识、该分支可查询终态或等价证明；已发送/未知结果的记录可见性保证和人工核实方式。需将`TaskCancellationResponse`中“ACCEPTED仅为受理”的笼统说明与操作描述统一，不新增前端猜测的SENDING枚举。
- 示例至少覆盖：FLOW 明确未发送、厂商明确拒绝、请求超时但已受理、发送中、运输先完成导致取消失败、取货后取消但尚未实物结算。
- 前端已调整：普通取消及位置解绑关联取消统一中性“处理中”文案；提交/查询404均保留原关联，查询提示明确非未发送/过期证明。503不因message出现FLOW/未发送而换UUID。ACCEPTED只查询不重发；CANCELLED仍须刷新位置及双方版本并检查阻塞、实物结算和`unbindEligibility`，不自动解绑。

## 5. 可取消任务清单：后端修正筛选及查询能力

**接口：** `GET /api/v1/business/nari-logistics/logistics/cancellable-tasks`

- 已明确：当前按`settled_time IS NULL`返回全部未结算任务，会混入取消处理中、未知、终态未结算及不支持分支。后端答复确认应修筛选，只返回当前允许取消的任务，不改业务要求，不转嫁前端。
- 仍需修正：后端筛选/分页总数/翻页结果应一致，排除不可取消项并给出验收样例；前端不根据状态/品牌/是否已有请求猜测资格。
- 本次同时发现：当前keyword实际匹配`task_no/origin_location_code/destination_location_code`，尚非已确认的“容器码/AGV编号或名称”；排序实际`id DESC`，不同于仓库原契约约定的`createdTime DESC、taskId DESC`（本次操作说明已不再保留该排序段）。请后端统一实现及约定，提供容器码、AGV编号、AGV名称查询和分页排序样例。
- 前端保持：统一扫码搜索及固定取消按钮；关键词原样传后端、结果沿用后端顺序，不增加客户端筛选/排序、不改成任务号/位置搜索。现有未决取消防重禁用不属于可取消资格筛选。

## 6. WMS 清理边界：固定 LES 范围不等于远端按申请隔离

**接口：** `POST /api/v1/business/nari-logistics/receiving/clear-wms-bindings`、`POST /api/v1/business/nari-logistics/shipping/submit`

- 边界已明确，可关闭“删除谓词不明确”问题：接收清理`mes_material_list`按箱码及`status=100`，发货`mes_material_records`复核完整来源多重集后按箱码删除、不加status；两者都不以`lCode`隔离申请。固定LES范围决定哪些箱，不保证箱内远端记录按本次申请隔离。
- 联调仍需验证：同箱多申请、来源变化、已有更新缴库记录、零匹配行及事务未知样例。局部新申请保护不等于能识别所有外部新申请，不能把它表述为全面跨申请隔离；后端仍需统一所有“仅当前任务”旧描述。
- 前端已同步：接收二次确认提示状态100及跨申请影响；发货对象卡提示不按状态/申请号隔离。不添加lCode或其他过滤参数，不自行缩小/扩大删除范围。后台保护、删除证据及事务由后端负责；本轮不执行真实删除，现场联调另行确认可恢复测试数据。
