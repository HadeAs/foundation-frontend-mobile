# Mock 开发与验收

当前登录、退出调用真实后端，必须能访问所选环境；其余已实现的接口默认使用本地 Mock，不访问业务后端。Mock 中未配置的接口返回明确错误，禁止回退到真实网络。保留 `VITE_API_MODE=real` 用于后续全量联调，本次不启用。原有库存、入库任务和容器管理服务本身使用本地模拟数据，暂保留其路由，但不再放入新首页。

## 登录与个人信息

- 使用有效后端账号密码登录；`admin / demo` 不再是应用中的演示登录方式。
- 用户 ID、姓名、账号和角色取真实登录响应；独立用户详情接口仍 Mock，部门暂显示“系统管理部”。
- 登录统一保存真实会话，不读取旧 `foundation.mobile.auth-session.mock`；退出清除本地真实会话，并调用真实退出接口，失败也不恢复会话。
- 版本号取当前应用资源版本。更新检查返回“无更新”，不下载或安装 WGT。
- 自动化业务测试通过 `seedTestSession` 注入测试会话，不访问真实服务；认证测试使用请求替身验证只有登录/退出走真实请求入口。

## 切回真实接口

默认无需环境文件。需要联调时在项目根目录 `.env.local` 设置 `VITE_API_MODE=real`，重启开发服务或重新打包。删除该设置或改为 `mock` 即恢复本地模式。正式发布前必须确认模式、接口环境和联调结果。

首页15个已确认入口均已接入 Mock，包括本次补齐的“物料接收”；这不代表真实后端联调完成。每个菜单仍需用户验收。

## 取消物流任务演示

进入菜单默认45条，统一扫码框按容器码、AGV编号或名称模糊查询；扫码或手动输入回车查询，点击×清除恢复全部。每页20条，触底加载、下拉刷新；取消按钮与当前状态/发起方式两行水平相邻。

| 搜索关键词 | 场景 |
| --- | --- |
| `CANCEL-NORMAL` / `AGV-001` | 二次确认后立即取消成功，刷新列表 |
| `CANCEL-ACCEPTED` | 先已受理，约3秒后查询得到最终取消成功 |
| `CANCEL-FAILED` | 已受理后查询得到设备拒绝原因，任务保留，可再次确认 |
| `CANCEL-UNKNOWN` | 已受理后结果未知，停止轮询，仅手动刷新结果 |
| `CANCEL-REJECTED` | 提交直接拒绝，保留任务及确认框 |
| `CANCEL-RESULT-FAIL` | 已受理后结果查询失败，保留手动查询入口 |
| `分页测试车` | 第二页首次失败，点击重试补齐后续记录 |
| `QUERY-FAIL` / 任意不匹配关键词 | 查询失败 / 空列表 |

“发起物流任务”新建的任务也可按容器码查询并取消；只有最终取消成功才解除该容器的未结束任务限制。Mock演示状态由接口决定，页面不按编码推断。任务ID包含大于JS安全整数的字符串，验证无精度损失。

未知取消结果不会自动重新提交。本地仅保存按模式、账号、环境隔离的未确认请求标识，离开页面停止轮询；同一次 Mock 会话返回时已受理请求恢复查询，未知请求保持手动查询。刷新应用或重置 Mock 数据会同时更换演示会话标识；旧 Mock 未决记录不再恢复，任务随内存数据恢复初始状态，可重新取消，无需手工清理缓存。旧版无会话标识的 Mock 记录同样不恢复。这不表示旧请求取消成功，仅表示演示重置；真实模式的未决记录不受影响，重启后仍须查询原请求，禁止重复提交。

Mock 的 SHIPPING 用途读取独立的内存 WMS 物料快照（这是演示假设，正式来源由后端定义），提交先保存快照与旧关系，再清理目标范围的 LES 板件绑定、重建本次绑定、清空对应 WMS 物料；料箱装车关系及库位关系保留，相关箱及载具聚合版本更新。旧关系和发货结果保存在内存操作历史中，不代表跨系统恢复方案已经实现。可用已开发的板件解绑/卸车查询核对新 LES 数据；重新发货查询同一对象显示无待处理物料。刷新应用恢复所有初始 Mock 数据和历史，不调用真实 LES/WMS。
